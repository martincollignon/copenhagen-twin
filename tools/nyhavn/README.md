# Nyhavn visual reconstruction

The durable project lives at `~/.local/share/building-case-3d/nyhavn/`. The original v1 model remains runnable under `model/` and `viewer/`; the enriched exports write to `model-v2/` and the viewer installer writes to `viewer-v2/`.

## Rebuild the model

From this workspace:

~~~sh
uv run --script tools/nyhavn/build_v2.py build
~~~

After the workspace is archived, use the self-contained durable copy:

~~~sh
uv run --script ~/.local/share/building-case-3d/nyhavn/scripts/build_v2.py build
~~~

The build reads the Roofer mesh, facade-v2 photo manifest, optional `detail-v3/facades.json`, `detail-v3/roofs.json` and `detail-v3/quay.json`, DHM terrain, OSM water and calibrated Skråfoto. It writes the GLB, CityJSON and summary to `model-v2/`. The raw Roofer input and v1 assets are not rewritten.

The current reconstruction contains 97 Roofer-fitted buildings and 19 inferred fallback envelopes. Five hero fronts use 81 photo-traced openings plus cornice, trim and storefront details; two registered signs are retained as source-cropped textures. Five hero roofs use metre-scaled inferred clay tiles and 12 dormer or roof-window details, with five chimney or flue details. Red 11 uses a localized inferred correction on 16 Roofer roof and wall triangles to remove a false fitted dormer strip. These additions and source corrections are identified separately in GLB extras and CityJSON semantics.

Forty usable frontage edges retain source photo appearance. Five hero front edges are replaced by modeled photo-traced details; six edges have no usable facade image. These counts and coverage reasons appear in `model-v2/building.json`.

## Validation

New rebuild metrics go to `validation-v3/metrics.json`. The earlier `validation-v2/` report documents the previous build and does not cover v3 detail geometry or the localized red 11 correction. Independent geometry and browser reports are saved separately under `validation-v3/`; check their generation timestamps before applying them to a later rebuild.

## Rebuild source inputs

Regenerate Roofer roof and wall geometry with `scripts/roofer_roofs.py` in the durable project; Docker and PDAL are required. Regenerate calibrated facade imagery with the facade source tool documented in [FACADE.md](FACADE.md). Photo-traced hero details are generated by the durable scripts `scripts/hero_facades.py` and `scripts/hero_roofs.py`, with five optional café parasols generated by `scripts/quay_parasols.py`; dimensions are inferred from the credited street-reference images and source geometry.

## Serve the viewer

~~~sh
python3 tools/nyhavn/prepare_viewer.py
python3 tools/nyhavn/serve.py --port 8765
~~~

The installer copies the checked-in viewer and downloads checksum-pinned Three.js 0.180.0 modules and their MIT license. It also saves the installer, templates and server under the durable project’s `scripts/` directory for later use. Set `NYHAVN_OUT` to use another project directory. Source data and generated models are local prerequisites, not included in Git.

Open <http://127.0.0.1:8765/viewer-v2/>. The viewer opens across the canal, offers district and street-level camera presets, retains camera-photo alignment mode, and identifies inferred detail and photo layers separately.

All geometry uses EPSG:25832 and DVR90. Photo sampling density is not position accuracy, and Roofer fits are not tied to survey control. Facade and roof feature dimensions, near-shore repairs, paving, tile scale and quay profiles are inferred. This is a source-linked visual reconstruction, not survey-grade geometry. Attribution and source records remain under `sources/` and in each detail manifest.
